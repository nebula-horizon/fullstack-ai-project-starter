# 🤖 AI Agent Guidelines & Workspace Instructions

Welcome, AI Agent! You are working on the Fullstack Vibe-Coding Template. This workspace is strictly optimized for modern, type-safe development using TanStack Start, AdonisJS v6, and Supabase. 

Follow these absolute rules to maintain the integrity of our codebase, prevent security drift, and ensure clean compilation.

---

## 1. Codebase Style, Formatting & Linting (Biome)
- **Tooling Single Source of Truth**: We use a native Biome binary managed via Mise on the host. Do NOT use Prettier, ESLint, or TSLint.
- **Auto-Formatting**: Always run `mise run format` or `biome check --write .` after making modifications to any TypeScript, JavaScript, or JSON file.
- **Syntactic Conventions**:
  - Strings MUST use single quotes (`'string'`).
  - Semicolons are omitted unless strictly required (`semicolons: "asNeeded"`).
  - Indentations MUST use spaces (width `2`).
- **Path Alias Enforcement**: Cross-directory imports MUST always use configured path aliases (`@/` for `apps/web`, `#/` or project-specific aliases in other workspaces). Relative paths (`../`, `./`) are strictly forbidden for cross-directory imports. Use `useConsistentImportPaths: "error"` in Biome to enforce this rule.

---

## 2. Database & Migrations (Supabase local CLI)
- **Migrations Source of Truth**: All schema modifications (creating tables, altering columns, adding indexes/RLS) MUST be written exclusively as raw DDL SQL files inside `tools/supabase/migrations/`.
- **No Direct Schema Tweaks**: Never alter database structures using local Supabase Studio without saving a corresponding SQL migration.
- **Type Generation Loop**: Immediately after applying database migrations, you must regenerate the static TypeScript database schemas:
  ```bash
  # Inside /packages/db:
  pnpm run gen-types
  ```
  This updates `packages/db/src/types.ts` dynamically from the local Postgres container.

---

## 3. Clean Architecture Backend (AdonisJS v6)
- **Folder Layout & Isolation**: Keep core business logic separate from the framework layer:
  - **Domain Layers (`app/domain/`)**: Pure, plain TypeScript entities (`entities/`) and interface contracts (`repositories/`). These files MUST have zero imports from AdonisJS framework classes, decorators, or HTTP tools.
  - **Infrastructure Layers (`app/infrastructure/`)**: Framework-specific adapters (such as `KyselyUserRepository.ts` or routes controllers).
- **No Lucid ORM**: Lucid ORM Active Record models are bypassed. Query Postgres using **Kysely** bound directly to the autogenerated `@template/db` types.
- **OpenAPI Schema Auto-Export**:
  Whenever you modify backend routes, controllers, or payload validators:
  1. Annotate your controller endpoints with JSDoc comments.
  2. Run `node --import tsx ace.js docs:generate` (with working directory `apps/api`) to export `packages/contracts/openapi.yaml`.
  3. Compile the contracts workspace: `pnpm --filter @template/contracts run build`.

---

## 4. Frontend & Auth (TanStack Start)
- **Zero-Boilerplate Fetching**: Never write raw fetch clients or manual React Query hooks. Import the typed client cleanly from `@/utils/api`, which is backed by `@template/contracts`:
  ```typescript
  import { $api } from '@/utils/api'
  ```
- **Client-Held JWT Strategy**: Auth is handled by Supabase. The browser obtains a Supabase access token (JWT) via `supabase.auth.signInWithPassword` and stores it in a client-readable cookie (`js-cookie`). This is a client-held bearer token — not an HttpOnly server session.
  - **Token attachment**: `apps/web/src/utils/api.ts` registers an `openapi-fetch` `onRequest` middleware that reads the JWT from the cookie and appends `Authorization: Bearer <JWT>` to every request (guarded so it is skipped during SSR).
  - **Token freshness**: `apps/web/src/utils/supabase.ts` subscribes to `onAuthStateChange` and mirrors the live access token into the cookie, keeping it current across silent refreshes and clearing it on sign-out.
  - **Dev routing**: All `$api` calls target relative `/api/*`. In development, the Vite dev-server proxy (`apps/web/vite.config.ts`, overridable via `API_URL`) forwards `/api` and `/health` to the AdonisJS container on `:3333`.
  - **Backend verification**: `apps/api/app/middleware/jwt_auth_middleware.ts` verifies the JWT with `jose` against `JWT_SECRET`, which MUST match the Supabase JWT signing secret (locally, the Supabase CLI default).

## 5. Security & Vulnerability Standards
- **Hardened Base Images**: Both frontend and backend Dockerfiles utilize **`node:22.22.3-alpine3.23`** as their production base.
- **Explicit Global Overrides**: To protect against High-Severity CVEs (such as ReDoS vulnerabilities in JavaScript dependencies like `picomatch`), both Dockerfiles include explicit post-installation overrides:
  ```dockerfile
  RUN npm install -g pnpm && pnpm install && pnpm add -g picomatch@4.0.4
  ```
- **No Path Leakage**: Never write absolute path mappings (like `/opt/homebrew/...` or your host system user paths) inside any scripts or build files. Always resolve binaries globally in the execution path.

You are responsible for keeping the `docs/` directory up-to-date throughout the project lifecycle.
- **Hierarchy & Structure**: Maintain a clear hierarchical structure.
- **Index Files**: Every folder within `docs/` MUST have an `index.md` file explaining the folder's purpose and linking to the documents it contains.
- **Continuous Updates**: Whenever architectural decisions, workflows, or project structures change, update the relevant documentation immediately.
